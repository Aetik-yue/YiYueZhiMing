# 2026-07-20 工作日志

## 修复：【小说】TXT / EPUB 导入全部静默失败

### 根因（最关键）
- `app/src/main/AndroidManifest.xml` 未禁用 WorkManager 默认自动初始化。合并清单里 `androidx.startup.InitializationProvider` 自动初始化了 `androidx.work.WorkManagerInitializer`，抢在 `YiYueApplication`（实现了 `Configuration.Provider` 并注入 `HiltWorkerFactory`）之前用默认配置初始化了 WorkManager。
- 结果：`@HiltWorker BookImportWorker` 没有无参构造器、又拿不到 Hilt 工厂 → **永远无法实例化**，`doWork()` 根本不执行 → TXT 和 EPUB 一律静默导入失败（与"两种都导入不了"现象完全吻合）。

### 改动 1：AndroidManifest.xml
- 根 `<manifest>` 增加 `xmlns:tools`。
- 在 `<application>` 内 merge `InitializationProvider` 并 `tools:node="remove"` 掉 `androidx.work.WorkManagerInitializer` 的 meta-data（保留 Emoji/lifecycle/profileinstaller 自动初始化）。
- 修复后 WorkManager 回退到 Application 的 `Configuration.Provider` → `HiltWorkerFactory` 生效 → 导入 worker 正常跑。

### 改动 2：EpubParser.kt（即便 worker 跑起来，EPUB 仍会失败的潜在坑）
- 原 `content.decodeToString()` 遇到非 UTF-8 字节直接抛异常 → "EPUB 解析失败"。改为 `decodeEntry()` 用 `CharsetDecoder` + `CodingErrorAction.REPLACE` 容错解码。
- 原 `entries[href]` 精确匹配：manifest 的 href 若含 URL 编码（%20/中文）或大小写不一致会整章丢失。新增 `findEntry()` 做多候选回退（原值/去./前缀/percentDecode/小写/反斜杠/baseName）。

### 验证建议
- 重新 build 安装后，小说页点「＋导入」选 TXT 与 EPUB，应出现 READY 书籍。
- Logcat 关注 `WorkManager`/`BookImportWorker`；若仍有失败，长按书籍会显示 `FAILED` 与 `errorMessage`。

## 追加修复：enqueueImport 主线程 I/O + 静默失败
- 用户要求一并修掉。改动：
  - `BookRepository.enqueueImport` 改为 `suspend`，整体用 `withContext(Dispatchers.IO)`，文件拷贝不再阻塞主线程（消除 ANR 风险）。
  - 拷贝失败时不再静默 `return`，改为返回 `ImportEnqueueResult.Failure(reason)`（reason 取异常信息或"文件为空/无法读取"），并清理 staging 文件。
  - 新增顶层 `sealed interface ImportEnqueueResult { Success / Failure(reason) }`。
  - `NovelBookshelfViewModel.import` 改用 `viewModelScope.launch` 调用挂起函数，成功/失败都通过 `state.message` 提示（失败会带具体原因，Snackbar 显示）。
- 调用方仅 `NovelBookshelfViewModel`，Screen 无需改动（import 仍是非挂起普通函数）。

## 排查：【小说】模块其余 bug（仅诊断，未改代码）
重点看了 NovelReaderViewModel / NovelReaderScreen / PaginationEngine / BookRepository / BookDao / Mapper。
1. 【高】阅读进度不恢复：`NovelReaderViewModel.init` 用两个独立 flow（observeBook / observeChapterMetas）。observeBook 里 `chapterIndex = if (chapterMetas.isEmpty()) book.currentChapterIndex else it.chapterIndex` —— 若章节 meta 先到达（chapterMetas 已非空），保存的 `book.currentChapterIndex` 被丢弃，重开书跳到第 0 章。更严重：`pageIndex` 从未从 `book.currentPageInChapter` 恢复，页内位置永远丢。持久层没问题（Mapper.kt:143-144、BookDao:45-46 都正确存/取）。需加 `restored` 标志，book+metas 都到齐后一次性用 book.currentChapterIndex/currentPageInChapter 恢复。

## 修复：阅读进度不恢复 + TXT 编码兜底抛异常（用户确认要修）
### 改动 A：`NovelReaderViewModel.kt`（阅读进度恢复）
- 删除原 `init` 里两个独立 flow 各自决定 `chapterIndex` 的逻辑（旧逻辑：observeBook 在 chapterMetas 非空时把 `book.currentChapterIndex` 整个丢弃；observeBook/observeChapterMetas 从不恢复 `pageIndex`）。
- 新增类字段 `progressRestored = false` 与私有方法 `maybeRestoreProgress(book)`：
  - 仅当 `progressRestored` 为假且 `chapterMetas` 已非空时才执行，一次性用 `book.currentChapterIndex`(coerce 到 [0, metas.size-1]) 与 `book.currentPageInChapter`(coerceAtLeast 0) 恢复位置，并 `loadChapter(chapterIndex, pageIndex)`。
  - 恢复后置 `progressRestored = true`，后续 observeBook/observeChapterMetas 的发射（含 saveProgress 触发的 book 更新回流）都不再覆盖已恢复的位置。
- 效果：读到第 N 章第 P 页，退出再进 → 回到第 N 章第 P 页（之前永远回到第 1 章第 1 页）。

### 改动 B：`BookRepository.readTextCompat`（TXT 编码兜底）
- 原最后兜底 `String(bytes, Charset.forName("GB18030"))` 走 REPORT 解码器，遇非法字节抛 `CharacterCodingException` → 冒泡到 importTxtInternal catch → TXT 导入失败。
- 改为 `GB18030.newDecoder().onMalformedInput(REPLACE).onUnmappableCharacter(REPLACE).decode(ByteBuffer.wrap(bytes)).toString()`，与 EpubParser.decodeEntry 一致，绝不再抛异常。

### 验证
- 需重新 build 安装。修 A 后：读几页退出再进应回到原位置；修 B 后：含异常字节的 TXT 也能成功导入而不报"解析失败"。

## 修复（续）：点按翻页 + 书架进度精确到页（用户"接着做"）
### 改动 C：`NovelReaderScreen.kt`（点按翻页）
- 原 `HorizontalPager` 的 `pointerInput` 只 `detectTapGestures { viewModel.toggleMenu() }`（点哪都只弹菜单）。
- 改为按点击横坐标分区：左 1/3 → `previousPage()`，右 1/3 → `nextPage()`，中间 → `toggleMenu()`。横向滑动翻页保留（pager 自身处理）。

### 改动 D：书架进度精确到页（新增 DB 列，非破坏性 Migration）
- 需求：书架进度条 `Book.progress` 原先仅按章粒度 `(currentChapterIndex+1)/totalChapters`，一章一跳。
- `BookEntity`/`Book`/`Mapper` 增加 `totalPages: Int`、`currentPageInBook: Int`（Book 加在构造参数末尾，带默认值，避免破坏既有调用）。`Book.progress` 改为：`totalPages>0` 时用 `currentPageInBook/totalPages`，否则降级回章级，并 `coerceIn(0,1)`。
- `YiYueDatabase` version 7→8；`AppModule` 注册 `MIGRATION_7_8`（`ALTER TABLE books ADD COLUMN totalPages/currentPageInBook INTEGER NOT NULL DEFAULT 0`），**非破坏性，老书数据不丢**；`fallbackToDestructiveMigration` 保留作兜底。
- `BookDao.updateProgress` 增加 `currentPageInBook`/`totalPages` 两列写入。
- `BookRepository.updateProgress(bookId, chapterIndex, pageIndex, pagesInChapter)`：维护会话内 `chapterPageCountCache`（首次按 `pagesJson` 解码构建每章页数），刷新当前章页数后算 `currentPageInBook = 前序章节页数之和 + pageIndex`、`totalPages = 全部章节页数之和` 并落库。翻页/改设置(reflow)都会更新，精度与当前阅读设置一致（未访问章节用导入时页数，读过后自修正）。
- 导入时（EPUB/TXT）分页即累加每章页数，`totalPages` 在 READY 落库，新导入书书架即显示页级进度。
- `NovelReaderViewModel.saveProgress` 现把 `_state.pages.size` 作为 `pagesInChapter` 传入；`repaginate`（改设置重排）末尾也 `saveProgress`，保证改设置后总页数刷新。

### 验证
- 重新 build 安装：阅读时点按屏幕左/右侧应翻上/下页，点中间弹菜单。
- 导入一本多章书后，书架进度条应随页内阅读平滑增长（不再整章跳变）；已升库的老书 `totalPages=0` 自动降级为章级，读一页后即转为页级。
